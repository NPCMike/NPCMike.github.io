Windows Kernel：物件管理、排程與驅動模型

Executive 子系統、OBJECT_HEADER、IRP 路徑，以及 kernel debugging 實務筆記。

#Windows Kernel#Driver#WinDbg

Kernel 不是「一個大程式」

Windows kernel 可拆成：

  • Microkernel 精神的分層 Executive（Process Manager、Memory Manager、I/O Manager…）
  • Kernel（排程、同步、中斷分派）
  • HAL（硬體抽象）
  • WDM/KMDF 驅動掛在 I/O stack 上

排程與 IRQL

Thread 排程發生在 PASSIVE_LEVEL 到 DISPATCH_LEVEL。驅動 writer 必記：

  • PASSIVE_LEVEL：可 pageable，可 wait
  • APC_LEVEL：APC 交付
  • DISPATCH_LEVEL：DPC 執行，不可 page fault
  • DIRQL：ISR 執行

Pool 與 PatchGuard

  • NonPagedPoolNx：核心資料結構、DMA buffer
  • PagedPool：可換頁，僅 PASSIVE/APC
  • PatchGuard (KPP)：週期性 hash 檢查 SSDT、IDT、GDT 等——hook kernel 在 production 上極危險
