Windows Internals：使用者模式與核心邊界

從 PE 載入、Process/Thread 到 syscall 分派，建立 Windows 執行模型的第一張地圖。

#Windows Internals#Reverse Engineering#PE

為什麼要讀 Windows Internals？

做惡意程式分析、驅動開發、或 EDR 繞過時，你需要的不是「會用 API」，而是知道呼叫鏈最後落在哪一層。Russinovich 的 Windows Internals 系列仍是基準，但實務上我會把重點壓在：

  • 執行單位：Process、Thread、Job Object
  • 記憶體管理：Virtual Address Descriptors (VAD)、Working Set
  • 物件管理器：HANDLE → _OBJECT_HEADER → 實體物件
  • I/O 子系統：IRP 路徑與 filter driver stack
Tip

現代 Windows 10/11 仍沿用此分層概念。差異主要在 PatchGuard、VBS/HVCI、以及 syscall 直接進 ntdll stub 的路徑優化。

記憶體：VAD 與 Private vs Image

Process 的 virtual address space 由 VAD tree（_MMVAD）描述。分析 dump 時：

  1. !vad（WinDbg）列出區段與 protection
  2. Private commit 常見於 heap、stack、注入的 RWX
  3. Image commit 對應 PE section 對映
Warning

PAGE_EXECUTE_READWRITE 單區域在現代 EDR 是強信号。實務 malware 常拆成 RW → 寫入 → VirtualProtect(RX)。
